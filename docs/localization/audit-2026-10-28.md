# Localization audit — 28 October 2026

Scope: shipped Spanish (es), French (fr), and Russian (ru). Source inspection and direct calls to the runtime translation functions; not an exhaustive playthrough. Follow-up: all listed gaps have now been translated in es/fr/ru and display wiring corrected, including developer screens. The findings below preserve the original audit.

## Existing checks

- `node tools/validate-i18n.mjs`: 877 keyed UI entries valid in each shipped translation.
- `node tools/audit-localization.mjs`: 751 scanned English content strings; zero reported missing translations.
- `node tools/test-event-localization.mjs`: passes, including 37 runtime story passages.
- Sanctuary labels and padded armor names have translations. Heartwood and Heart of the Briars names also have translations.

These checks do not establish full runtime coverage. The content audit has an explicit module list that omits traps and most runtime feedback. Key parity only checks keys already registered.

## Wiring gaps

- `src/systems/board/BoardCardFx.js:1149`: boss attack text is assigned directly as `ATK ${...}`. Use a localized stat label/template.
- `src/systems/board/CocoonCacheBoard.js:384`: hatching uses raw `newData.name` and appends `!` before sending it to combat feedback. Translate the enemy name first and use a localized announcement template. Its fallback `Enemy!` also lacks a translation; the normal loot result `Opened!` is counted above.

## Lower-priority and conditional screens

- `src/scenes/SanctuaryPreviewScene.js`: developer preview hardcodes its heading, buttons, restoration counter, statue names and effects. The actual Sanctuary uses keyed translations.
- `src/ui/CombatHud.js`: developer item vault includes `OPEN`, `ITEM`, `DEBUG ITEM VAULT`, `Added: ...`, and a hardcoded English `on` between sigil and item names.
- `src/scenes/ShopScene.js:464`: `Shop — ${offer.rarity} amulet` is passed as a raw heading. Currently the single-amulet path records this in telemetry instead of drawing the choice overlay; localize if the multi-choice overlay is restored.

## Suggested order

1. Translate trap names and the 16 missing runtime message examples above with placeholders.
2. Localize the boss ATK label and cocoon announcement assembly.
3. Extend the audit to trap definitions and runtime feedback, including optional calls and multiline calls. The present audit can pass with these gaps.
4. Decide whether developer screens need translation, then check long translations in the narrow pedestal labels visually.

Companion damage captions such as Skeleton Slash, Chick Zap and Spider Bite were checked with an actual numerical prefix and do translate; they are intentionally excluded. German is not offered as a shipped language and was not treated as a release blocker.

## Runtime HUD follow-up

A browser check found a context bug that dictionary coverage cannot detect:
CombatHud is mixed into GameScene, so `this` is the scene and `this.scene` is
Phaser's ScenePlugin. Passing the plugin to `t()` / `tCount()` selected English.
Fixed the floor banner and all affected player-effect calls to pass the actual
scene, and made the banner use the location-name translation key.

Additional runtime gaps fixed: coin/crystal pickup captions now translate their
currency and source (Prospector's Pick, Lucky, and crystal-finding companions).
The new `test:hud-localization` browser suite verifies the floor banner, 17
status/buff entries and six reward/source combinations in es/fr/ru.

Location identifiers such as Thornwake are currently proper names with the same
spelling in the existing locale tables. Descriptive location subtitles are
translated. Older companion names are save-migration aliases; developer console
messages are not player UI. No claim of exhaustive localization follows from
passing the content/key audits alone.

# Game code audit — October 14, 2026

Audited the current working checkout, including its existing uncommitted changes. Gameplay code and assets were not changed. The audit adds this report, a repeatable headless audit harness, and its evidence JSON.

Six bugs were reproduced. The most urgent is lost progress when using Save & Quit from the rest or anvil options menu.

## Findings

### 1. P1 — Save & Quit in rest/anvil does not save the run

Location: `src/scenes/PauseMenuScene.js:141`, with callers at `src/scenes/RestScene.js:97` and `src/scenes/AnvilScene.js:89`.

These rooms launch the pause menu with their own scene key. `quitToMainMenu()` looks up that scene as `gameScene`, then saves only if it has `saveCurrentRun()`. Neither room has that method. The routine also stops the selected room and several overlays without stopping the actual `GameScene` in this case.

Trigger: enter a rest room or repair equipment at the anvil, open its cog, and choose Save & Quit. Continue restores the earlier map checkpoint, losing the visit's healing or repairs and associated state changes. A headless call with `pausedScene: 'RestScene'` produced zero save calls and no stop for `GameScene`.

Suggested fix: resolve the run owner separately from the paused scene, always save through `GameScene`, and stop it on exit. Keep normal Resume directed at the selected room.

### 2. P2 — Save & Quit can erase enemies' owed responses

Locations: `src/systems/combat/CombatTurnController.js:59`, `:164`; `src/managers/SaveManager.js:150`; `src/scenes/GameScene.js:1492`.

Player actions queue enemy turns with a 500 ms delay. The run save records the resulting player/board state but no pending enemy-turn count, current attacker position, or combat phase. Restoring the room explicitly clears enemy-turn timers.

Trigger: attack a surviving enemy, then pause and save before its response. Continue preserves the attack and spent resources but drops the corresponding retaliation. Saving between attackers can likewise skip the remaining attackers. The harness queued two responses and confirmed that neither was represented in the saved state.

Suggested fix: save at a settled turn boundary, or persist enough combat phase and queue information to resume outstanding responses exactly once. Add a regression check for both a queued turn and a partially completed multi-enemy response.

### 3. P2 — Combat status flags disappear on Continue

Locations: `src/managers/SaveManager.js:189`, `:310`; `src/scenes/GameScene.js:1861`; defaults at `src/systems/GameState.js:65`.

The save preserves `playerEffects` but omits `playerSpored` and `playerStunnedTurns`, which are stored separately. New state initializes these flags to false/zero and the load routine never restores them.

Trigger: save while affected by a Spore Archer or goblin stun. Continue clears the penalty. The harness saved `playerSpored: true` and `playerStunnedTurns: 1`; neither survived in the saved effects. Once-per-floor talent flags such as `keenEdgeUsedThisFloor` also deserve inclusion if that talent system is enabled.

Suggested fix: explicitly serialize and restore all active combat flags with backward-compatible defaults. Add a status round-trip test through the real scene loader.

### 4. P2 — Deferred music can miss a scene transition

Location: `src/audio/MusicManager.js:46`, `:58`.

If a track is already downloading, a later scene's request exits before updating ownership or registering its interest. Completion still checks whether the original requesting scene is active. If the original scene has left, playback is abandoned even though the next scene requested the same track.

Trigger: start a new game before the menu track finishes downloading; the village requests the same theme. The harness reproduced zero playback calls after completion with the destination active, both with and without an intervening stop request. This primarily affects cold loads or slower connections.

Suggested fix: let a persistent audio scene own downloads and remember the latest requesting scene and playback parameters. Clear pending state on cancellation/error and handle requests made while a download is already in flight.

### 5. P2 — Chain armor loses its counter on its final durability point

Location: `src/systems/combat/PlayerDamageResolver.js:229`, `:272`.

The hit's protection is calculated first, then durability is spent. If the armor breaks, `equippedArmor` becomes null before its counter chance is read. That same hit still benefits from its protection but cannot trigger its counter. The Reprisal check has the same dependency when talents are enabled.

Reproduction: with identical attack, protection, and a forced successful counter roll, armor at two durability blocked two damage and countered for one. Armor at one durability still blocked two but produced no counter.

Suggested fix: capture the armor that participates in the hit and use its properties for that hit's reactions, even if it breaks during resolution. Handle destruction separately from the current hit's effect eligibility.

### 6. P2 — Storage failures can abort scene creation or progression

Locations: `src/managers/MetaProgressionManager.js:51`, `:135`; `src/audio/VolumeSettings.js:25`; `src/scenes/MainMenuScene.js:630`.

Several active paths call localStorage directly, despite guarded helpers elsewhere. The meta manager's initial read is outside its parse try/catch; volume settings writes and the menu's language read are also unguarded.

Trigger: storage is denied by browser settings or a write exceeds its quota. The harness made `getItem()` throw and confirmed that constructing `MetaProgressionManager` throws immediately. The menu and progression call paths have similar unguarded operations.

Suggested fix: use one guarded storage adapter for reads/writes/removals, retain in-memory settings when persistence fails, and return save success/failure to callers.

## Optimization opportunities

1. **Update HUD objects in place.** `src/ui/CombatHud.js:709` calls armor, amulet, relic, and status updates for ordinary stat changes. Armor is destroyed/recreated at `:976`, and the amulet/status groups are cleared at `:1113` and `:1580`. Reuse sprites and text, update only changed values, and rebuild collection layouts only when membership changes. This should reduce object allocation, text texture regeneration, and listener churn. No frame-rate improvement has been measured yet.

2. **Remove completed turn timers from the retained list.** `src/systems/combat/CombatTurnController.js:169`, `:296` and companion paths append timer references; cleanup clears the whole list on transitions rather than retiring each completed timer. The harness completed 100 scheduled callbacks and still found 100 retained references. Use a Set with removal on completion or prune the array. This is bounded by a room transition, rather than an unlimited whole-session leak.

3. **Compare save versions numerically.** `src/managers/SaveManager.js:242` compares strings. A future `1.0.10` sorts before `1.0.6` and would be rejected as incompatible. This is a maintenance issue, not a failure of the current `1.0.7` version.
